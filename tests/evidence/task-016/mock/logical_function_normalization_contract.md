# Task 016 Logical Function normalization mock contract

- Contract version: `task016-logical-function-mock-v2`. A candidate Logical Function is a review proposal comparing distinct, still-separate Task 014 operation and canonical API identities.
- Every comparison retains the Task 014 operation ID, Task 015 Observed Function ID, source provenance/fingerprint, provisional action/object wording, HTTP contract, backend certainty, transformation-policy evidence and missing information for both sides.
- Allowed proposal statuses are `POSSIBLE_SAME_LOGICAL_FUNCTION`, `CLEARLY_DIFFERENT_SUPPORTED`, `NOT_COMPARABLE_DUE_TO_MISSING_EVIDENCE`, and `REVIEW_REQUIRED_CONFLICTING_SIGNALS`. None means confirmed duplicate, approved sameness, safe replacement, retirement, Logical API, domain, capability or Kong design.
- Candidate generation is bounded to eight accepted Task 014 structural-overlap pairs and two indexed negative controls. No all-pairs or full-estate grouping is performed.
- Method/path, name/version, provisional wording, or backend identity alone cannot prove sameness. Positive and negative evidence remain separate, and actual safely resolved request/response shape differences are compared where available.
- Exact operation-scoped configuration and API-shared candidate context remain distinct. Neither configuration layer proves runtime use; candidate context never proves operation egress.
- Task 015 confidence is automated interpretation evidence strength, not business accuracy or API quality. Missing staging metadata is not a production defect or evidence of inactivity.
- Assembly transformation policies are recorded by type and source pointer only; raw values are omitted. Schema descriptions, examples and data values are omitted.
- All proposals remain `PENDING_REVIEW`, preserve distinct IDs, and require Integration/Enterprise Architect validation. Confluence is only `CONFLUENCE_POTENTIAL_UNVERIFIED` for specific future evidence requests and was not accessed.
- The mock is deterministic and used no language model; measured model token usage is zero.
